# Changing systems

Treat change as a transition from an existing system to a successor. Installing new behavior does not complete the change.

## Preserve why the current system exists

Ask:

> **What changed that makes a different system appropriate now?**

Record what the current system does and why it exists. Preserve its history instead of rewriting it to make the successor look inevitable.

When the condition that justified an intervention disappears, reassess whether the intervention should remain.

## Change the existing state

A new design says what should happen next. A transition must also account for what already exists.

Determine how the successor treats each affected item. Keep anything undiscovered visible as unknown rather than assuming it is unaffected.

Separate the desired destination from the path that reaches it. The path must remain recoverable if the change stops halfway through.

## Finish the predecessor

Retirement ends the predecessor's effects without erasing the history that still matters. Its visible state should match reality.

Stop when the successor works and every discovered existing item has a truthful disposition.
