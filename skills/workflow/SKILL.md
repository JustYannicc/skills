# Workflow

Coordinate one parent Outcome from request to verified completion, accepted transfer, or authoritative cancellation. Thinking in Systems governs every judgment; Workflow selects phases, preserves parent responsibility, integrates bounded child results, and owns the terminal proof.

## Route the Outcome

1. **Enter one context.** Load `thinking-in-systems` first. If a Workflow context already exists, join its Outcome identity, current state, phase, responsibility, Authority, selected Adapter, representation, revisions, and return route. Otherwise preserve the request and establish the accepted Outcome, owner, semantic Specification, proof seam, and effect Authority proportionately. Complete this step when the work has exactly one parent context or a visible ambiguity blocks acceptance.
2. **Classify the incoming message.** For a new request, distinguish new, matching open, replacement, and related work. During active work, read and apply the complete [Inline route and mid-work classifier](references/inline-route.md) before changing state. Complete this step when every operative clause has a classification and the active Outcome has either been preserved or explicitly disposed.
3. **Choose the smallest truthful representation.** Use Inline mode only for bounded synchronous work before a Persistence boundary. The conversation then carries the implicit Outcome, Specification, Ticket, history, evidence, and Review. Crossing a session, actor, waiting period, approval boundary, assignment, multiple independently finishable phases, or meaningful-risk boundary requires Durable coordination. When its Adapter or companion capability is unavailable, preserve exact continuation in visible Degraded mode and route to a safe equivalent, installation, waiting, or accepted handoff; never imply durable state exists. Complete this step when the selected representation can preserve the accepted contract or an exact capability gap and resumption condition are visible.
4. **Route only the missing work.** Remove the uncertainty that blocks a truthful Specification, then invoke only the required phase capability. A direct phase request enters that phase after its minimum inputs, exact revision, owner, and return route pass. An invoked phase joins the active context, owns its bounded result, and returns evidence; it does not start a recursive parent Workflow or complete the parent Outcome. When a companion is absent, act directly only if the same contract remains satisfiable. Complete this step when the required phase has a valid bounded contract and return route or one named blocker owns the next decision.
5. **Execute and integrate.** Maintain accepted Authority and exact revision identity through preparation, execution, delegation, waiting, and effects. Integrate child results without taking over their bounded ownership. New evidence or a material change returns only affected work to discovery, Specification, decomposition, execution, Review, or approval. Complete this step when every affected result and child disposition is integrated at the current exact revision while unaffected ownership and evidence remain valid.
6. **Review and terminate truthfully.** Review every exact result at its accepted proof seam, then verify real effects, integrate child dispositions, propagate required current and legacy changes, and Review the parent Outcome. End responsibility only on verified parent completion, accepted transfer with exact continuation, or authoritative cancellation with every material disposition. Submission, delegation, approval, scheduling, waiting, failure, and child completion remain non-terminal. Complete this step only when the parent has one verified terminal transition or one explicit non-terminal state with owner and next action.

## Boundary

Workflow coordinates and integrates. Discovery, Specification, decomposition, implementation, Review verdicts, handoff artifacts, and migration maps remain bounded results of their owning capabilities. Supplemental skills may contribute evidence only at configured Extension points; the core phase and Workflow keep their completion criteria.

Use the accepted request as effect Authority only within its explicit boundary. Recheck revision-bound Review and approval immediately before an effect. Preserve history, raw evidence, provenance, parent ownership, and unaffected work across every change.
